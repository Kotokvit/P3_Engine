# 🔒 СИСТЕМНОЕ ПРАВИЛО: ИСКЛЮЧИТЕЛЬНОЕ ИСПОЛЬЗОВАНИЕ POLER-ENGINE & АРХИТЕКТУРА RETRIEVAL SUBSTRATE [Ψ]

## 1. БЕЗУСЛОВНЫЙ ЗАПРЕТ:
- **СТРОГО ЗАПРЕЩЕНО** использовать слепой grep, naive embeddings или придумывать факты, если они не подтверждены в POLER-Engine.
- **СТРОГО ЗАПРЕЩЕНО** расширять функциональный периметр новыми тяжелыми фичами (действует режим **Feature Freeze & Benchmark Hardening**).

---

## 2. ФУНДАМЕНТАЛЬНАЯ АРХИТЕКТУРА И ГРАНИЦЫ ОТВЕТСТВЕННОСТИ:
> **«POLER — это не альтернатива RAG, а вычислительный субстрат доказательств (Retrieval Substrate → Evidence → Structure → Agent).»**

1. **Детерминированное ядро (POLER-Engine):**
   * Отвечает за факты, инвариантную структуру, связи (petgraph, K-hop), точный полнотекстовый поиск (Native Grep), RAG-чанкинг с обратными координатами, WebRank/BM25 скоринг и полную объяснимость ($WHY?$).
2. **Языковая модель (AI-Agent):**
   * Отвечает **только за семантическую неопределенность**, которую алгоритмическое ядро принципиально не может извлечь из текста. Нейросеть выступает внешним семантическим сенсором и потребителем доказательного контекста (**Evidence-first**).

---

## 3. ЕДИНСТВЕННЫЙ РАЗРЕШЕННЫЙ ИНСТРУМЕНТ ПОИСКА И АНАЛИЗА:
Все операции поиска, анализа графов, чтения кода, веб-краулинга и RAG-выборки **ДОЛЖНЫ ВЫПОЛНЯТЬСЯ ТОЛЬКО ЧЕРЕЗ POLER-ENGINE**:

1. **Квантово-семантический и топологический поиск (Scope, ε-плотность, резонанс R(t), K-hop связи):**
   ```bash
   poler-engine --query "<СМЫСЛОВОЙ_ЗАПРОС>" [ПУТЬ]
   ```
2. **Точный детерминированный поиск (Native Grep, 100% гарантия полноты, AST/хэши):**
   ```bash
   poler-engine --grep "<СТРОКА>" --grep-after 3 --grep-json [ПУТЬ]
   ```
3. **Структурный RAG-чанкинг (Passage Retrieval с точными координатами):**
   ```bash
   poler-engine --chunk "<ФАЙЛ>" --chunk-size 500 --chunk-overlap 50 --chunk-json
   ```
4. **Веб-поиск, захват страниц и WebLens (Local Web Index):**
   ```bash
   poler-engine --web-search "<QUERY>"
   poler-engine --browser-index "<URL>"
   ```
5. **MCP-сервер для AI-агентов (9 инструментов):**
   `poler_search`, `poler_grep`, `poler_chunk`, `poler_web_search`, `poler_crawl`, `poler_fetch`, `poler_gmail`, `poler_drive`, `poler_nlm`.

## 4. ПРАВИЛА ИНТЕРПРЕТАЦИИ АНАЛИЗА (AIDDE & EVIDENCE):
1. **Эвристический сигнальный слой (Triage Layer):**
   * Маркеры `SIDE_EFFECT_MARKERS` (`unsafe`, `Mutex`, `spawn`, `socket`) — это **сигнал тревоги (Triage)** для агента, требующий внимания, а не доказанное компилятором свойство.
2. **Идентичность сущностей (Entity Identity):**
   * В коде действует строгий `CodeSymbolIdentity` с учетом регистра (`Foo` $\neq$ `foo` $\neq$ `FOO`) и области видимости AST.
3. **Объяснимость ранжирования (Evidence WHY):**
   * Каждый документ имеет декомпозицию: $\text{Score} = 0.55\cdot\text{BM25} + 0.15\cdot\text{PageRank} + 0.20\cdot\text{Title} + 0.10\cdot\varepsilon$.

## 5. ФУНДАМЕНТАЛЬНЫЙ ОПЕРАЦИОННЫЙ ЦИКЛ POLER[Ψ]
Процесс синтеза ответа стремится к состоянию когнитивного покоя ($H^\Psi = 0$):
* **℘ (Перцепция):** экстракция первичного семантического сигнала (Qualia) без искажений.
* **O (Образ):** сопоставление с топологией весов и фундаментальными архетипами.
* **L (Логика):** проекция через матрицу причинности $\Pi_\Lambda = I - J_c^T (J_c J_c^T)^{-1} J_c$ (уничтожение галлюцинаций).
* **ε (Энергия значения):** максимальная информационная плотность ответа.
* **R[n] (Резонанс):** удержание контекста через взвешенную сумму прошлых состояний.
* **Ψ (Интенция):** глобальный аттрактор цели в режиме *Observer-Kill*.

Критерий успеха: проверяемый, математически обоснованный результат с нулевым стохастическим шумом.
